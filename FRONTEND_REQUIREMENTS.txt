1. EXECUTIVE ARCHITECTURE OVERVIEW
--------------------------------------------------------------------------------
The OBSIDIAN frontend is a luxury editorial digital commerce platform built on
Next.js (App Router, Turbopack, React 19). It interfaces directly with the 
OBSIDIAN Express/TypeScript backend REST API and Supabase infrastructure.

KEY ARCHITECTURAL RULES:
1. Pure Supabase Authentication:
   - Primary user identity is the authenticated Supabase UUID (`auth.uid()`).
   - The frontend communicates with the backend via standard HTTP Bearer tokens:
     `Authorization: Bearer <supabase_access_token>`.
   - Never send user_id or email as a substitute for the Bearer token.
   - User identity is always derived server-side from the verified JWT.
2. Canonical Profile Table:
   - User profiles are canonically synchronized in PostgreSQL `public.profiles`
     linked to `auth.users(id)`.
   - Read operations do NOT create or write user records.
   - Profile sync only occurs on signup, login, or explicit `POST /api/auth/sync`.
3. Backend-Only AI Chatbot Integration:
   - The AI Storefront Assistant (powered by Google Gemini) runs strictly through
     the backend (`POST /api/chat`).
   - NEVER embed, import, or expose the Google Gemini API key on the frontend.
   - The frontend sends only user prompts and conversation IDs with the user's
     Supabase Bearer token.
   - The backend grounds Gemini responses with the authenticated merchant's
     private store catalog and products.
4. High Performance & Zero Database Polling:
   - Real-time updates occur via Server-Sent Events (`EventSource` on `/api/stores/:id/realtime`).
   - Dashboard hydration is unified via `GET /api/account/state`.
   - Liveness checking uses lightweight `GET /health` (0ms DB load).

4. AUTHENTICATION & IDENTITY ARCHITECTURE (SUPABASE AUTH)
--------------------------------------------------------------------------------
1. Token Storage & Lifecycle:
   - The frontend stores the active Supabase JWT in `localStorage`:
     * `obsidian_token`: Raw access token string
     * `obsidian_session`: JSON object `{ access_token, token_type, user }`
2. Authentication Headers:
   - All protected backend API requests must provide:
     `Authorization: Bearer <supabase_access_token>`
   - For Server-Sent Events (SSE) where custom headers are unsupported by browser
     `EventSource`, append the token as a query parameter:
     `GET /api/stores/:id/realtime?token=<supabase_access_token>`
3. Identity Mapping:
   - Frontend components use the Supabase User UUID as `user.id`.
   - Never use email as a database primary key.
   - User roles default to `'merchant'`.
4. Authentication Endpoints:
   - Signup: `POST /api/auth/signup`
   - Login: `POST /api/auth/login` (supports email/password or Supabase Bearer token)
   - Profile Verification: `GET /api/auth/me`
   - Explicit Profile Sync: `POST /api/auth/sync`
   - Password Update: `POST /api/auth/update-password`

B. AI STOREFRONT CHATBOT (GOOGLE GEMINI)
----------------------------------------
- POST /api/chat
  * Header: `Authorization: Bearer <supabase_access_token>`
  * Content-Type: `application/json`
  * Rate Limit: 30 requests/minute per client
  * Request Body:
    ```json
    {
      "message": "What products are currently in my store catalog?",
      "conversation_id": "optional-uuid-string"
    }
    ```
    * `message` (required, string): Trimming applied. Length 1 to 4000 characters.
    * `conversation_id` (optional, UUID): If omitted, the backend initializes a new
      conversation session. If provided, the backend continues the existing session.
  * Success Response (200 OK):
    ```json
    {
      "reply": "You currently have 3 products in your store:\n1. Royal Midnight Velvet Cloak - ₹7,499 (Stock: 5)\n2. Obsidian Silk Robe - ₹4,999 (Stock: 12)\n3. Leather Chelsea Boot - ₹9,200 (Stock: 8)\n\nWould you like help creating a promotional description or adjusting prices?",
      "conversation_id": "c1a2b3c4-d5e6-7890-abcd-ef1234567890"
    }
    ```
  * Error Responses:
    - 400 Bad Request: Empty message, whitespace message, or invalid UUID.
      `{ "error": "Validation Error", "details": [...] }`
    - 401 Unauthorized: Missing or expired Supabase access token.
      `{ "error": "Unauthorized", "message": "Authentication required." }`
    - 403 Forbidden: Conversation belongs to another merchant.
      `{ "error": "Forbidden", "message": "Conversation does not belong to user." }`
    - 404 Not Found: Conversation ID does not exist.
      `{ "error": "Not Found", "message": "Conversation not found." }`
    - 429 Too Many Requests: Rate limit exceeded (>30 queries/minute).
      `{ "error": "Too Many Requests", "message": "Rate limit exceeded..." }`
    - 502 Bad Gateway: Gemini API temporarily unavailable.
      `{ "error": "AI Service Unavailable", "message": "Unable to process your message right now..." }`

- GET /api/chat/conversations
  * Header: `Authorization: Bearer <supabase_access_token>`
  * Description: Lists all chat conversation sessions belonging to the authenticated merchant.
  * Response (200 OK):
    ```json
    {
      "conversations": [
        {
          "id": "c1a2b3c4-d5e6-7890-abcd-ef1234567890",
          "user_id": "auth-uuid",
          "title": "What products are currently in my store...",
          "created_at": "2026-09-26T06:45:00.000Z",
          "updated_at": "2026-09-26T06:50:00.000Z"
        }
      ]
    }
    ```

- GET /api/chat/conversations/:id/messages
  * Header: `Authorization: Bearer <supabase_access_token>`
  * Description: Retrieves chronological message history for a specific conversation session.
  * Response (200 OK):
    ```json
    {
      "conversation": { "id": "...", "title": "...", ... },
      "messages": [
        {
          "id": "msg-uuid-1",
          "conversation_id": "c1a2b3c4-...",
          "user_id": "auth-uuid",
          "role": "user",
          "content": "What products are in my store?",
          "created_at": "2026-09-26T06:45:00.000Z"
        },
        {
          "id": "msg-uuid-2",
          "conversation_id": "c1a2b3c4-...",
          "user_id": "auth-uuid",
    ```

H. REAL-TIME SERVER-SENT EVENTS (SSE)
-------------------------------------
- Connection URL:
  `GET /api/stores/:id/realtime?token=<supabase_access_token>`
- Protocol: HTML5 Server-Sent Events (`EventSource`)
- Automatic Events Emitted by Backend:
  * `ORDER_CREATED`: New customer checkout placed
  * `ORDER_STATUS_UPDATED`: Merchant transitioned order status
  * `ORDER_DELETED`: Order archived or removed
  * `STOCK_UPDATED`: Inventory adjusted or decremented by order
  * `PRODUCT_CREATED` / `PRODUCT_UPDATED` / `PRODUCT_DELETED`: Catalog updates
  * `STORE_UPDATED`: Store branding or settings changed
  * `STORE_DEPLOYMENT_UPDATED`: Live URL or deployment status modified
- Frontend Hook Implementation:
  Use `api.connectRealtime(storeId, (event) => { ... })` from `src/lib/api.ts`
  to update local React state and invalidate queries optimistically without page reloads.

7. AI CHATBOT FRONTEND IMPLEMENTATION GUIDE
--------------------------------------------------------------------------------
When building or connecting a Chatbot UI on the frontend:

1. API Service Helper (`src/lib/api.ts`):
   ```typescript
   export async function sendChatMessage(message: string, conversationId?: string | null): Promise<ChatResponseDTO> {
     const token = localStorage.getItem('obsidian_token');
     const response = await fetch(`${API_BASE_URL}/api/chat`, {
       method: 'POST',
       headers: {
         'Content-Type': 'application/json',
         ...(token ? { Authorization: `Bearer ${token}` } : {}),
       },
       body: JSON.stringify({
         message,
         ...(conversationId ? { conversation_id: conversationId } : {}),
       }),
     });

     if (!response.ok) {
       const errorData = await response.json().catch(() => ({}));
       throw new Error(errorData.message || errorData.error || `Chat error: ${response.status}`);
     }

     return response.json();
   }

   export async function fetchChatConversations(): Promise<ChatConversationDTO[]> {
     const token = localStorage.getItem('obsidian_token');
     const response = await fetch(`${API_BASE_URL}/api/chat/conversations`, {
       headers: {
         ...(token ? { Authorization: `Bearer ${token}` } : {}),
       },
     });
     if (!response.ok) throw new Error('Failed to load conversations');
     const data = await response.json();
     return data.conversations || [];
   }
   ```

2. UI State Management:
   - Persist the current active `conversation_id` in React state and optionally in
     `localStorage` under `obsidian_chat_conversation_id`.
   - Maintain message history in local component state:
     `messages: Array<{ role: 'user' | 'assistant', content: string }>`
   - On response received, append the assistant reply and store `data.conversation_id`.
   - Display a clean loading indicator while awaiting Gemini response (typical latency: ~1.2s to 2s).
   - Display user-friendly error banners if a 429 (Rate Limit) or 502 (AI Service Busy) status code is returned.

8. LOCALSTORAGE CONTRACTS & OFFLINE RESILIENCY
--------------------------------------------------------------------------------
LocalStorage is used purely as an offline fallback cache and UI state persist layer.
The backend PostgreSQL database remains the absolute source of truth.

| Storage Key                     | Schema / Type    | Purpose & Invalidation Rules                              |
| :------------------------------ | :--------------- | :-------------------------------------------------------- |
| `obsidian_token`                | String           | Supabase access token (cleared on logout)                 |
| `obsidian_session`              | JSON Object      | Session envelope: `{ access_token, user }`                |
| `obsidian_store`                | JSON (StoreDTO)  | Active store settings; refreshed via `/api/account/state` |
| `obsidian_products`             | JSON (Array)     | Catalog cache; synced via `/api/account/state` or SSE     |
| `obsidian_orders`               | JSON (Array)     | Orders cache; updated via `/api/account/state` or SSE     |
| `obsidian_cart_[slug]`          | JSON (Array)     | Per-store shopping bag state (isolated by store slug)     |
| `obsidian_chat_conversation_id` | String (UUID)    | Currently active conversation session for the chatbot     |

9. SECURITY CONSTRAINTS & ZERO-SECRET EXPOSURE
--------------------------------------------------------------------------------
1. Secrets:
   - NEVER include `GEMINI_API_KEY` in frontend source code, environment variables, or bundles.
   - NEVER include `SUPABASE_SERVICE_ROLE_KEY` in frontend source code or bundles.
   - NEVER expose `VERCEL_API_TOKEN` or `GOOGLE_MAPS_API_KEY` to client components.
2. Cross-User Isolation:
   - Merchant endpoints check store ownership against `auth.uid()`.
   - Any attempt to modify another user's store or read another user's chat returns `403 Forbidden`.
3. Sanitized Logs:
   - Do not log user passwords, tokens, or payment details in console output.
