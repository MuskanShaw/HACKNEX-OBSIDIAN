4. STATE MANAGEMENT & LOCALSTORAGE CONTRACTS
--------------------------------------------------------------------------------
The frontend uses synchronous LocalStorage for offline resiliency, fallback state,
and session management:

| Key Name              | Data Type | Purpose & Lifecycle                                         |
| :-------------------- | :-------- | :---------------------------------------------------------- |
| `obsidian_token`      | String    | JWT Bearer token obtained from login/registration           |
| `obsidian_session`    | JSON Object| Current authenticated merchant profile (`id`, `email`, `role`)|
| `obsidian_store`      | JSON Object| Currently active store configuration & branding settings    |
| `obsidian_products`   | JSON Array| Cached catalog items for offline demo mode                  |
| `obsidian_orders`     | JSON Array| Cached orders for instant rendering and optimistic updates  |
| `obsidian_cart_[slug]`| JSON Array| Per-store customer shopping cart state (`items`, `quantities`)|

5. BACKEND API CONSUMPTION & CLIENT CONTRACT (`src/lib/api.ts`)
--------------------------------------------------------------------------------
All API calls pass through `API_BASE_URL` with automatic Bearer token injection:

- Base URL Resolution:
  1. `process.env.NEXT_PUBLIC_BACKEND_URL`
  2. `process.env.NEXT_PUBLIC_API_URL`
  3. Fallback: `https://hacknex-obsidian.onrender.com`

- Auth Header:
  `Authorization: Bearer <obsidian_token>` (injected on all protected requests)

- Consumed Endpoints:
  * `POST   /api/auth/register`       - Register new merchant account
  * `POST   /api/auth/login`          - Merchant login and token issuance
  * `GET    /api/auth/me`             - Verify token and fetch merchant profile
  * `POST   /api/stores`              - Create new store configuration
  * `GET    /api/stores/my-store`     - Fetch merchant's active store
  * `PUT    /api/stores/[id]`         - Update store settings & branding
  * `GET    /api/stores/[slug]`       - Fetch public store data by slug
  * `GET    /api/products`            - List products for active store
  * `POST   /api/products`            - Add new product to store
  * `PUT    /api/products/[id]`       - Update existing product or stock
  * `DELETE /api/products/[id]`       - Remove product from store
  * `GET    /api/orders`              - List incoming store orders
  * `POST   /api/orders`              - Place customer order from storefront
  * `PATCH  /api/orders/[id]/status`  - Update order fulfillment status
  * `GET    /api/analytics/dashboard` - Fetch aggregated revenue and sales trends
